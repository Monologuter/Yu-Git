# 驭Git 视觉设计简报

> 这份文件是给 Claude Design 的 Design system 用的上传材料。
> 它描述**现状、约束和要解决的问题**，不描述解决方案——方案是设计要产出的东西。

## 产品

macOS 原生 Git 客户端，界面全中文，面向中文开发者。
定位是「AI 写代码的时代，帮你驾驭 AI 产出的改动」。

用户是资深开发者，**每天连续盯着它 6–8 小时**，处理成千上万行代码差异。
这个使用强度决定了两件事：长时间不能累，信息密度不能低。

## 当前的问题（要解决的）

1. **零视觉辨识度。** 全部使用 macOS 系统语义色，保证了不出错，
   也保证了不出彩——截图里没有任何一处能认出这是驭Git。
2. **commit graph 太弱。** 线宽 1.8pt、用系统色板，而这是 Git 客户端的门面，
   第一眼印象几乎全来自它。GitKraken 用 3pt 粗线和高饱和色板，
   视觉冲击力远超我们。
3. **列表缺少节奏。** 提交列表每一行长得完全一样，眼睛没有落点。
4. **空状态平淡。** 直接用系统的 ContentUnavailableView。

## 硬约束

### 必须像 Mac 原生应用

这是产品的核心卖点之一（对标 Electron 的 GitKraken）。因此：

- 使用系统标准窗口按钮、SF Pro 字体、系统控件样式
- 侧栏应使用 vibrancy 半透明材质（这是 Electron 做不到的质感）
- **所有效果必须能用 SwiftUI + AppKit 标准能力实现**：
  不要复杂渐变、多层阴影、自定义字体、需要图片资源的装饰
- 深浅色模式都必须成立，且深浅切换是 macOS 系统级的，
  正交于主题——即「4 套主题 × 浅/深 = 8 组色值」

### 信息密度优先于留白

用户是专业工具的重度使用者。同样宽度下能多显示 5 行提交，
比留白好看更有价值。GitKraken 在这一点上做错了。

### 颜色的语义占用

- **红和绿已被 diff 占用**（新增/删除），任何其他用途都不能用纯红纯绿，
  否则造成语义混淆。分支图色板尤其要避开。
- **纯蓝是 macOS 系统默认强调色**，用它做品牌色等于没有品牌色。

### 无障碍

- 正文对比度 ≥ 4.5:1，大字 ≥ 3:1（WCAG AA）
- 分支图的 8 色对红绿色盲可区分
- 不能仅靠颜色传达信息（状态要有字母或图标）

## 现有的设计 token（在 Yugit/DesignSystem/Theme.swift）

保留这套结构，只改数值。

### 间距（4pt 网格）

| 名称 | 值 | 用途 |
|---|---|---|
| hairline | 2 | 同一行内紧密相关的两个元素 |
| tight | 4 | 一组内部 |
| regular | 8 | 默认 |
| loose | 12 | 相关的两组之间 |
| section | 16 | 区块之间 |
| major | 24 | 大块留白 |

跟随 4pt 网格是因为 macOS 系统控件本身按此设计，跟着排才能对齐。

### 圆角

small 4（徽章）/ medium 6（按钮、输入框）/ large 10（卡片、面板）

### 字体（只有 4 档，刻意压得少）

| 名称 | 现值 | 用途 |
|---|---|---|
| body | 13pt regular | 提交标题、文件名 |
| secondary | 11pt regular | 作者、分支名 |
| title | 15pt semibold | 面板标题 |
| mono | 11pt monospaced | hash、行号、diff 正文 |

档位再多，视觉层次反而会糊——读者分辨不出 12 和 13 的差别。
**注意：等宽字体只用于 hash 和代码。中文字形本身等宽，
人名和标题套西文等宽会破坏字距。**

### 分支图色板（现状，需要重做）

现在直接用 8 个系统色：systemBlue、systemPurple、systemTeal、systemOrange、
systemIndigo、systemPink、systemBrown、systemCyan。

问题：这 8 个系统色**明度不一致**，几条线画在一起显得脏。
需要重新设计一组等明度、高饱和、相邻色相拉开的色板。

### 关键绘制参数（commit graph）

| 参数 | 现值 | 备注 |
|---|---|---|
| 轨道水平间距 | 14pt | |
| 曲线线宽 | 1.8pt | **太细，需要加粗** |
| 节点半径 | 4pt | 实心圆，中心挖空以便在密集连线中辨认 |
| 图形区最大宽度 | 84pt | 上限，超出则压缩轨道间距 |
| 行高 | 44pt | 两行文字：标题 + (hash·作者·时间) |

选中行的特殊处理：选中背景是强调色，此时曲线和节点**必须换成
能压住强调色背景的前景色**，否则蓝线画在蓝底上会消失。

### diff 配色（现状）

- 新增行：整行 green.opacity(0.12)，词级变化处叠加 green.opacity(0.28)
- 删除行：同上，红色
- **两层要能叠加且代码文字仍清晰可读**，这是最容易出问题的地方

语法高亮 5 类：关键字、字符串、注释、数字、类型名。
现用 purple / brown / secondary / orange / teal，同样避开红绿。

## 界面结构

三栏，从左到右：

**左栏 260pt**——过滤框 + 本地分支 / 远程分支（可折叠带计数）/ 标签。
分支行：图标 + 名称 + ahead/behind 指示。当前分支加粗并有主色标记。

**中栏 380pt**——分段控件「变更 N | 历史」。历史模式是提交列表，
即上面描述的 commit graph + 两行文字。

**右栏 剩余**——提交详情（标题、hash 带复制按钮、作者、父提交）+
改动文件列表（A/M/D 状态字母用语义色）+ 下半部分是 diff 视图
（双列行号 + 语法高亮 + 增删底色 + 词级底色），中间有可拖动分隔条。

**工具栏**——仓库名 + 分支 / 右侧：获取、拉取、推送、更多菜单。

## 需要产出的四套主题

| 主题 | 场景 | 特征 |
|---|---|---|
| 默认 | 大多数人 | 克制，最接近原生，跟随系统强调色 |
| 墨 | 长时间连续使用 | 低对比暖调，非重点元素明显后退 |
| 昼 | 强光环境、投屏演示 | 高对比，边框明确，色盲友好 |
| 谱 | 喜欢代码编辑器审美 | 饱和度最高，视觉张力最强 |

**先只做「默认」的浅色一套**，风格确认后再扩展其余。
一次产出 8 组，风格不对就是全废。

## 参照

**要学的**：Linear 和 Xcode 26 的克制专业感；GitKraken 把 commit graph
画得有表现力这一点（唯一值得学的地方）。

**不要学的**：GitKraken 的低信息密度、自绘控件、Electron 观感、
高饱和深色游戏风。

## 交付格式

除了视觉稿，请以**文本**形式列出所有数值，格式：

```
名称 | 浅色 hex | 深色 hex | 用途
```

尺寸类同理列出具体 pt 值。图片无法直接取色，文本数值才能落进代码。
