# 驭Git（Yugit）实现计划

> 本文是 `02-产品需求文档.md` 的工程落地版，里程碑编号与 PRD 版本节奏严格对齐。
> 前身为 `~/.claude/plans/macos-app-mighty-kahn.md`（旧代号 dkyCoco），已按 PRD 重排并补齐缺项。

## 1. 技术决策（已确认，勿擅自推翻）

| 决策点 | 结论 |
|---|---|
| 技术栈 | Swift + SwiftUI/AppKit 原生，目标 macOS 14+，Apple Silicon 优先 |
| Git 引擎 | **调用系统 git CLI + porcelain 解析**（不用 libgit2/SwiftGit2）——唯一让用户 credential helper / SSH config / hooks 原样生效的方案；SwiftGit2 已停止维护 |
| AI 接入 | BYOK：OpenAI 兼容接口（DeepSeek/通义/OpenAI/Ollama/自定义 baseURL）+ Anthropic 接口；Key 存 Keychain |
| 分发 | Developer ID 签名 + 公证，**不开沙盒**、暂不上 App Store（沙盒与访问系统 git / 任意仓库路径 / SSH agent 硬冲突） |
| 并发模型 | Swift Concurrency；每仓库一个 actor 串行化写操作，防止互踩 `index.lock` |

### 架构概要

SPM 组织：App target + 三个本地 Package，依赖单向：

```
Yugit (App: SwiftUI/AppKit UI + ViewModel + AI 编排)
   ├──► GitKit      (纯 Foundation：ProcessRunner / GitClient / 各 Parser / RepoActor / FSEvents)
   ├──► TimelineKit (纯 Foundation：OperationLog / SnapshotStore / UndoPlanner)   ← v0.5 落地，v0.1 预留接口
   └──► AIKit       (纯 Foundation：AIProvider 协议 / OpenAI + Anthropic 两实现 / SSE 解析 / Keychain)
```

**UI 分工**：窗口壳、侧栏、变更列表、提交框、设置、AI 面板、时间线侧栏全用 SwiftUI（`NavigationSplitView` 三栏：侧栏 / 变更·历史 / diff 详情）；仅两处用 AppKit 保性能——**提交历史列表 + 自绘分支图**（`NSTableView` + CoreGraphics）和 **diff 查看器**（行级虚拟化 `NSTableView`，hunk 头行带「暂存此块」按钮）。

**Git CLI 关键细节**：
- GUI 无 shell 环境 → 启动时经 login shell 解析 PATH 缓存注入（否则 credential helper 找不到）
- 全部命令 `GIT_TERMINAL_PROMPT=0` + 超时可取消
- 解析统一 `-z` NUL 分隔 + `core.quotepath=false`（中文/空格文件名）
- 后台刷新加 `--no-optional-locks`
- 每仓库一个 `git cat-file --batch` 长驻进程加速取文件内容

**AI 层**：`AIProvider` 协议 + `AsyncThrowingStream<ChatEvent>` 流式；Anthropic 的 system 是顶层字段、SSE 是命名事件流，与 OpenAI 兼容格式在协议层抹平。diff 过大时分层截断：stat 概览永远保留 → 过滤 lockfile/生成文件 → 按改动重要性装填至约 24K 字符预算 → 兜底只发概览。`.env` / credential 类敏感文件内容默认不进 prompt。

## 2. 贯穿全程的架构约束（早埋，晚补要返工）

这三条不是某个里程碑的功能，是从 v0.1 第一行代码就要成立的地基：

1. **所有仓库写操作必须经由 `RepoActor.perform(_ op: GitOperation)` 单一入口**——时间线 Undo（支柱 1）要求每个操作可记录、可命名、可逆推。v0.1 阶段该入口只做串行化 + 日志落盘，快照与回滚在 v0.5 接上，但**入口形状必须一次定对**。绕过入口直接 `run("git", ...)` 的写操作视为 bug。
2. **每个 `GitOperation` 自带「等价 git 命令 + 中文注解」元数据**——透明命令层（差异化 ⑦）和 Command Palette 直接消费这份元数据，不是事后给每个 UI 动作补文案。
3. **解析器与 patch 生成器同构**——DiffParser 解出的结构，PatchBuilder 必须能原样还原回可 `git apply` 的 patch。这是 hunk/行级暂存不损坏工作区的根本保证，用往返测试（round-trip test）锁死。

### v0.2 — 提交工作流 · 自举（2–3 周）

**做什么**

**验收**

- 外部改动（终端/agent 写文件）≤ 500ms 反映到 UI

### v0.5 — 公开 Beta：第一个传播点（3–4 周）

**做什么**
- **仓库时间线 + 无畏 Undo（支柱 1）**：TimelineKit 落地——operation log + 工作区快照、时间线侧栏、全局 Cmd+Z、外部/agent 改动自动快照点
- **Command Palette + 透明命令**：Cmd+K 面板；每个操作显示等价 git 命令 + 中文注解（消费第 2 节约束 2 的元数据）
- **AI 基础能力（BYOK）**：AIKit 落地 + 设置页（多 provider、Keychain、测试连接）、AI commit message（流式进提交框、可编辑）、中文解释 commit / diff / branch
- 可视化 interactive rebase（**自动 backup tag** 安全网）+ Quick Actions（右键一步 squash 等高频意图）

**快照技术方案**（本阶段最大技术风险，方案先定）
用独立 index 把工作区写成 tree 对象，存进私有 ref 命名空间，**不污染用户的 stash 栈、reflog 和 branch**：

```
GIT_INDEX_FILE=<tmp>/yugit-snap.idx  git add -A
git write-tree  →  git commit-tree  →  更新 refs/yugit/timeline/<id>
```

- `refs/yugit/*` 不会被 push、不进 `git log`，但 ref 存在即免于 gc
- 大仓库成本控制：防抖 + 仅在写操作前后与检测到外部改动静默期后打点；超出保留窗口的快照按策略清理 ref
- 恢复 = `git read-tree` + `git checkout-index`，恢复动作本身也记一条 operation（Undo 可再 Undo）

**验收**
- DeepSeek 和 Anthropic 真实 key 各跑通；5000+ 行 diff 截断生效；错误 key / 断网 / 取消均有明确中文反馈
- 终端里 `git reset --hard` 造成的破坏能从时间线恢复（覆盖 Claude Code `/rewind` 的空位——**这是传播点本身**）
- 快照打点在 5 万 commit 仓库上不产生可感知卡顿

## 4. 关键风险与规避

| # | 风险 | 规避 | 兑现节点 |
|---|---|---|---|
| 1 | **Process 管道死锁**（git 大输出必踩） | ProcessRunner 并发排空 stdout/stderr | v0.1 第一件事 |
| 2 | 凭据挂起 / GUI 找不到 helper | `GIT_TERMINAL_PROMPT=0` + login shell PATH 注入 | v0.1 / v0.3 |
| 3 | **hunk / 行级暂存损坏文件**（CRLF、无尾换行） | patch 生成与 DiffParser 同构 + 往返测试 + 专项 fixture；失败回退整文件 stage | v0.2 |
| 4 | 大 diff 渲染卡死 | 行级虚拟化；单文件 > 10K 行折叠为点击展开 | v0.2 |
| 5 | FSEvents 刷新风暴 | 300ms 防抖；自身执行 git 期间挂起 watcher | v0.2 |
| 6 | **快照污染用户仓库 / 拖慢大仓库** | 私有 `refs/yugit/*` 命名空间 + 独立 GIT_INDEX_FILE + 防抖打点 + 保留窗口清理 | v0.5 |
| 7 | AI 隐私（diff 含密钥外发） | 首次使用告知 + 敏感文件过滤 + 发送前显示上下文体积 | v0.5 |
| 8 | 时间线入口被绕过导致 Undo 有洞 | 所有写操作走 `RepoActor.perform`；加 lint/测试断言 GitKit 内无旁路写调用 | v0.1 立规矩 |

## 5. 执行方式与验证

1. 从 v0.1 开始实现，每个里程碑按验收标准验证后再进入下一个
2. **每修一个 git 边缘 case 就补一个 fixture 回归测试**（`swift test` 跑 GitKit / TimelineKit / AIKit 单测）
3. v0.2 起以「用驭Git 开发驭Git」作为持续端到端验证
4. 端到端性能验证：clone 一个知名开源大库（如 llvm/linux）跑 PRD 第 5 节全部指标
5. AI 验证：真实 DeepSeek / Anthropic key 走通生成与解释，验证截断与错误处理
