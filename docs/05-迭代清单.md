# 迭代清单

> 这份文件是 **agent 持续迭代的依据**，也是人看进度的地方。
>
> 存在的理由：新会话的 agent 读不到上一次会话的上下文。没有这份清单，
> 每次都要从代码里重新推断该做什么，而「为什么这么排优先级」「哪些已经
> 试过不行」这类信息根本推断不出来。
>
> **动了任何一项就回来更新状态。** 清单和代码不同步，比没有清单更糟——
> 那会让人照着过时的信息做决定。

## 怎么用

- 状态：`[ ]` 待办 · `[~]` 进行中 · `[x]` 完成 · `[-]` 放弃（写明理由）
- 每项都要有**验收标准**，否则「做完了」是没法判断的
- 优先级 P0 最高。P0 没清空之前不要开 P1
- 完成一项就 commit + push（提交信息用英文，见 `docs/04` §3）

## 需要人拍板的（agent 不要自己决定）

这几类必须停下来问，不要替用户做主：

- **审美判断**——配色好不好看、间距舒不舒服，只能人看了说
- **优先级变更**——清单顺序调整
- **不可逆操作**——改写已推送的历史、删分支、吊销证书
- **对外发布**——打 tag、发 Release、改仓库描述
- **引入第三方依赖**——需要书面论证（`docs/04` §4）
- **许可证与商业模式**相关的任何改动

## P1 · 功能缺口（被拿去和 Fork/GitKraken 比时会输的）

`docs/01` 把这些列进了 table stakes。

- [ ] **stash 完整管理**——现在能 stash，但没有可视化列表、预览、部分应用
- [ ] **submodule 支持**——状态显示、更新、递归操作
- [ ] **LFS 支持**——至少要能识别并正确显示，不能把指针文件当普通文本
- [ ] **GPG 签名提交**——`docs/01` 点名 ugit 因为缺这个被批评
- [ ] **多仓库切换器**——最近仓库 + 快速切换 + 跨仓库搜索。
      **不做** GitKraken 那种 Workspaces 抽象：那是给团队协作设计的，
      我们的用户多是个人同时开 3–5 个项目
- [ ] **Issue 引用识别**——提交信息里的 `#123` 变成可点链接，显示标题与状态。
      **不做**完整的 issue 管理，那是网页和 IDE 的地盘

## P2 · 深化差异化（护城河）

这几项 GitKraken 没有、也不太可能做。

- [ ] **时间线深化**
      - 恢复前预览：告诉用户「退回这个点，工作区会变成什么样」（现在是盲跳）
      - 选择性恢复：只恢复某几个文件
      - 快照语义标注：「Claude 第 3 轮改动前」而不是「操作 17」
      - 快照过期策略：现在会无限堆积
- [ ] **Commit Composer 深化**
      - 按语义边界而非文件边界拆（同一文件的两处改动可能属于不同提交）
      - 提交顺序建议：让每个中间状态都能编译通过，否则 bisect 无意义
      - 拆完之后每个 commit 各自过一遍 AI 评审
- [ ] **worktree 变成 agent 指挥台**
      - 每个 worktree 显示对应的 agent 会话状态
      - 跨 worktree 的改动汇总，一屏看全
      - 冲突预警：两个 agent 改了同一文件时提前告警
- [ ] **归因 blame 深化**——从「这行是 AI 写的」到「哪次对话、哪个 prompt」
- [ ] **MCP Server**（我认为差异化最大的一项）
      - 把驭Git 的能力暴露给 Claude Code：打快照、拆提交、查时间线
      - 意义在于**方向反转**：现在是驭Git 调 AI，MCP 让 Claude Code 调驭Git。
        GUI 成为 agent 的操作台，而不是 agent 的替代品——
        这才是 slogan「AI 帮你写代码，驭Git 帮你驾驭它」真正兑现的样子
      - GitKraken 做不了这件事，因为它不在开发者的终端工作流里

## P3 · 质量与技术债

- [ ] **性能实测**——PRD 第 5 节的指标至今没有在真实大仓库上验过
      - 5 万 commit 首屏 500ms、滚动 60fps、内存 <150MB
      - 需要写成可重复的基准脚本，不是手动点一遍
- [ ] **UI 层测试覆盖**——现在几乎为零。这次踩的三个 bug
      （`.task(id:)` 重复触发、语法高亮死循环、选中行分支图消失）
      **没有一个**会被现有测试抓到
- [ ] **diff 视图的 AppKit 虚拟化**——现在是 SwiftUI `LazyVStack`，
      超过 2000 行就折叠。`docs/03` 原计划 v0.3 换 AppKit，一直没做
- [ ] **快照仓库体积**——`refs/yugit/*` 会无限增长，需要 gc 策略

## 明确不做

写在这里是为了避免反复讨论。

- **Windows / Linux**——核心卖点之一是「原生」，跨平台等于放弃它。
  GitKraken 就是前车之鉴
- **上 App Store**——沙盒会限制对任意路径 git 仓库的访问
- **对基础功能收订阅**——`docs/02` 的商业模式铁律，本地 Git 全功能永久免费
- **自绘控件替代系统控件**——那是 Electron 应用的做法，我们的差异点恰好相反
